# ALINDA UI Structure — Phase 1

## Public Booking Page

1. Slim top bar
2. Business identity block
3. Service list
4. Date rail
5. Time-slot grid
6. Customer information form
7. Sticky/primary booking action
8. Confirmation state

### Visual priority

`Business identity → Service → Date → Time → Customer details → Confirm`

The customer should always understand what step they are on and what they have already selected.

## Business Panel

### Sidebar

- Overview
- Randevular
- Hizmetler
- Çalışma Saatleri
- İşletme Ayarları

### Dashboard

- Welcome/header area
- Today's appointment summary
- Upcoming appointments
- Quick actions
- Small activity/booking summary

## First Prototype Screen

The first coded screen will be the public business page because it establishes the product's visual identity and booking UX before the internal panel is built.

Prototype data will be static at first. Firebase and real booking logic come later in the relevant phases.
